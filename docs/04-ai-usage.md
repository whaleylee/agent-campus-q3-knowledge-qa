## 2. AI 辅助范围

以下内容由 AI 辅助生成，我逐项审阅修改后采用：

1. **初版工具函数**（`src/tools.py` 的检索计分与故障注入骨架）——AI 生成，我核对过计分只依赖 docs.json 的 keywords、排序按得分降序。
2. **ReAct 循环骨架**（`src/agent.py`）——AI 生成，我核对了 JSON 提取的容错（截取首尾大括号）和工具异常兜底。
3. **测试用例初稿**——AI 生成，断言细节是我补的，比如 case-02 里断言 answer 不能出现"以新版本为准"。
4. **文档初稿**——docs/02、03 由 AI 起草，里面的数字都取自 `examples/*/output.json` 和 pytest 实际输出，我逐条对过。

## 3. 本人修改（AI 初版没有、由我决策引入的内容）

1. **冲突判定改成文本对比**：AI 初版用正则从两段原文里抽"N 天"比大小。我把 D02 的"15 天"改成"15 个工作日"重跑，它判不出冲突了——这意味着评审换个措辞，它就会单边作答，直接踩"冲突不得择一"的红线。我改成两段原文归一化后直接文本对比，单位怎么写都管。`test_conflict_detection_survives_unit_wording_change` 就是这次改动补的回归测试。
2. **追问定位不匹配句式**：AI 初版靠正则找"哪份/那份"来识别追问，题面明说固定句式匹配不算 ReAct。我改成拿问题里的数值和已读原文直接比对，恰好一篇命中就定位。换成"规定 15 个工作日的是哪个文件来着"这种问法，结果不变。
3. **改写词表外置到 data/terms.json**：AI 初版把"打卡→考勤"写死在代码里。外置之后加词条就扩行为，我还加了一层"从文档关键词反查"兜底，测试里换了一张"食堂→后勤"的表验证过。
4. **两个取舍是我拍的板**：引用校验宁可误拦不可错引（逐字比对，只做空白归一化）；冲突不按版本日期裁决（版本新旧是数据属性，不是效力依据）。

## 4. 验证方式

- `PYTHONUTF8=1 python -m pytest -q`：28 个测试全绿，含上面四条对应的回归测试。
- `PYTHONUTF8=1 python run_examples.py`：7 个用例产物全部重新生成，和 docs/03 的表格对得上。
- 手工核验，我自己动手做过三件事：
  1. 把 docs.json 里 D03 的"5 天年假"改成"8 天"，重跑 case-01，回答跟着变成 8 天；
  2. 把问法从"报销期限是多久"换成"报销的钱多久内要交上去"，它照样命中 D01、D02 并列冲突；
  3. 随手抽了 case-02 的引用片段，和 docs.json 里 D01 原文逐字核对，一字不差。

## 5. 候选人补充

**我在哪些环节有自己的判断**：冲突判定那次返工最典型。第一版"能跑通"是假象——测试全绿只说明合成数据没变过。我后来给自己立了个规矩：每条决策逻辑都要问一句"评审换掉数据它还成立吗"，问倒了的就重写。第 3 节的四条都是这么来的。

**我否决掉的方案**：让模型自己判断两份文档是否冲突（在 prompt 里把规则写清楚就行）。放弃的原因是这属于红线判定，交给提示词等于靠模型自觉，最后做成了代码里对两次 read_doc 结果的文本比对。

**我的手工验证记录**：见第 4 节的三件事，都在 git 历史里有对应时间点；改数据重放的操作没有落成自动化脚本，是我手动改 JSON 重跑的。
