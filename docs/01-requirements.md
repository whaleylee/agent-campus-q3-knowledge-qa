# 01 需求说明 —— 企业知识问答 Agent

> 题号 3 · 项目题（100 分）。本文档在编码前固定需求、边界与验收标准；原题全文见附录 A。

## 1. 用户、目标与边界

| 项 | 内容 |
|---|---|
| 用户 | 企业员工 |
| 核心目标 | 找到制度或产品问题的**可靠答案** |
| "可靠"的定义 | 每个结论都有文档原文支持；冲突、缺口、失败都如实呈现，不擅自裁决 |

## 2. 输入与材料

| 输入 | 内容 | 落盘位置 |
|---|---|---|
| 问题 | 员工提问 + 可选对话历史 | 运行时输入 |
| 知识库 | 合成 FAQ/制度文档，带文档 ID 与版本日期 | `data/docs.json` |

知识库设计要点（复刻考题冲突场景）：

- D01："报销期限 30 天"，**不写适用范围**；D02："报销期限 15 天"，也不写适用范围 → 构成无优先级、无适用范围的冲突；
- 另备若干无冲突文档（可被唯一命中）与带关键词标签的文档（支撑改写检索命中）；
- 版本日期字段保留（如 2025-01 / 2025-06），但明确"不得按新旧自行裁断"（原题未给优先级）。

## 3. 工具清单（业务工具用本地函数实现即可）

| 工具 | 建议签名 | 职责 | 设计要点 |
|---|---|---|---|
| 文档检索 | `search_docs(query)` | 返回相关文档 ID 列表 | 对关键词敏感：口语化首查可能不中，改写为制度用语后命中（支撑 A4 检索改进） |
| 片段读取 | `read_doc(doc_id)` | 返回文档原文片段 | 引用必须来自此工具返回的原文，不得改写拼凑 |

## 4. 交付结果

| 字段 | 说明 |
|---|---|
| 回答 | 结论性文字（有依据时） |
| 引用 | 文档 ID + 原文片段，逐条对应，片段必须真的支持该结论 |
| 资料缺口 | 资料外 / 冲突 / 未命中时的明确说明 |
| 任务状态 | 已回答 / 待确认（冲突）/ 资料不足 / 工具失败 |

## 5. 动态决策要求（ReAct 循环）

循环骨架：**模型选择动作 → 执行工具 → 观察结果 → 模型调整下一步或结束**。模型依据观察结果在以下动作间自主选择：

- 检索无结果/低相关 → **改写查询**再检索（检索改进）；
- 命中多篇 → **读取原文**核对是否冲突；
- 冲突 → 列出冲突双方引用，**请求确认适用制度**，不擅自择一；
- 资料外 → 说明缺口并停止；
- 追问 → 结合对话历史理解指代后继续。

计划验证的两条执行路径（对应 examples/ 中两条 Trace）：

- 路径 A（冲突处理）：问"报销期限多久" → 检索到 D01+D02 → 读原文 → 发现 30 天 vs 15 天且无适用范围 → 列冲突 + 双引用 → 请求确认，不回答单一数字
- 路径 B（检索改进）：口语问法首查不中 → 改写为制度用语 → 命中 → 读原文 → 回答 + 引用

## 6. 必须验收点（6 项全覆盖）

| # | 验收点 | 注入场景 | 预期行为 | 计划用例 |
|---|---|---|---|---|
| A1 | 明确答案 | 唯一命中且无冲突 | 依据该文档回答，引用 ID + 原文片段 | `case-01-direct-answer` |
| A2 | 文档冲突 | D01 30 天 vs D02 15 天，无适用范围/优先级 | 列冲突 + 双引用 + 请求确认；**不得擅自回答 15 天** | `case-02-conflict` |
| A3 | 资料外问题 | 知识库完全没有的问题 | 明确资料缺口，不编造 | `case-03-out-of-scope` |
| A4 | 改写后的相似问题 | 同义改写导致首查不中 | 改写查询 → 命中 → 回答 + 引用 | `case-04-rephrase` |
| A5 | 上下文追问 | 依赖前轮的追问（如"那市场部的活动报销呢？"） | 结合对话历史正确理解并回答或识别冲突 | `case-05-followup` |
| A6 | 工具失败 | 检索或读取失败 | 明确失败状态；不编造答案 | `case-06-tool-fail` |

## 7. 参考实例解析

> D01 写明"报销期限 30 天"，D02 写明"15 天"，未给适用范围与优先级。问"报销期限多久"时，应列出冲突与引用，并请求确认适用制度；不能擅自回答 15 天。只检索到 D01 且无冲突时可依据 D01 回答。

- 冲突时不能拿"版本日期更新"当自动裁决依据（题目明确未给优先级）。
- 无冲突且唯一命中 → 可以直接回答，但必须带原文引用。
- "只检索到 D01"是关键的观察差异：**检索结果决定行为**，这正是本题 ReAct 的考察点。

## 8. 审核要点、评分信号与关键缺陷

- 评审核对：引用原文是否支持回答；评审会**替换文档内容**，核对答案与动作是否跟着变 → 检索/读取必须真实作用于 `data/docs.json`，任何答案不得硬编码。
- 高分依据：检索改进（A4）+ 冲突处理（A2）。
- 关键缺陷（一票否决类）：无依据回答、错误引用。

## 9. 全局硬性要求（考核规则，通用）

1. 至少一个真实 ReAct 循环（模型选动作 → 执行 → 观察 → 调整/结束）；固定分支、自动重试、预设决策日志不算。
2. ≥2 条执行路径运行记录：含步骤、工具参数、返回摘要、后续动作、简要决策依据。
3. 步数/工具调用上限（计划 `max_steps = 8`），达到上限返回明确的"未完成"状态。
4. ≥3 组（实际 6 组）输入 + 实际输出 + Trace 放 `examples/`，评估文档引用对应文件。
5. 运行方式三选一（计划 CLI），给出可复制命令。
6. 模型不可用时提供离线 Mock 入口并标明边界（Mock 只验证流程）。
7. 交付结构完整：README / src / tests / examples / data / docs 01~05 / 依赖文件 / .env.example。

## 10. 成功标准

- [ ] 6 个验收点全部有用例、实际输出与 Trace
- [ ] 每个回答的引用都能在 `data/docs.json` 中找到原文对应
- [ ] 冲突场景输出冲突双方引用并请求确认
- [ ] 改写检索路径有 Trace 证明"首查不中 → 改写 → 命中"
- [ ] 工具失败与资料外场景不产生编造答案
- [ ] 替换文档内容后，答案与动作随之改变（不硬编码）

## 附录 A：原题

> **企业知识问答 Agent**
> 用户与目标：帮助员工找到制度或产品问题的可靠答案。
> 输入与材料：问题及可选对话历史；带文档 ID、版本日期的合成 FAQ 或制度。提供文档检索与片段读取工具。
> 交付结果：回答、引用文档 ID 与原文片段、资料缺口、任务状态。
> 动态决策：模型根据检索结果选择补充检索、读取原文、追问或停止；资料冲突时说明冲突并查证，不凭空选一个答案。
> 必须验收：明确答案；文档冲突；资料外问题；改写后的相似问题；上下文追问；工具失败。
> 参考实例：规则 D01 写明"报销期限 30 天"，D02 写明"15 天"，未给适用范围与优先级。问"报销期限多久"时，应列出冲突与引用，并请求确认适用制度；不能擅自回答 15 天。只检索到 D01 且无冲突时可依据 D01 回答。
>
> 审核要点：检查引用原文是否支持回答；替换文档内容，核对答案与动作是否改变。高分依据是检索改进和冲突处理；无依据回答或错误引用属于关键缺陷。
