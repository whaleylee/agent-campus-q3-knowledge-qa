# 05 复盘 —— 最难问题、学习收获与下一步

## 1. 最难的问题

**冲突判定的"反背题"改造。** 初版用正则从两段原文里抽"N 天"比较大小来判断冲突，写测试时意识到这其实是把出题人的示例（30 天/15 天）写进了代码：评审把 D02 改成"15 个工作日"，判定直接失效，而漏判冲突意味着单边作答——恰好是本题一票否决的红线。重构为归一化文本对比后，判定不再依赖任何领域措辞，单位怎么写都能判冲突。教训：**测试要防的不是"当前数据跑不通"，而是"数据被替换后行为不变味"**。

## 2. 学习收获

1. **"观察→变招"必须发生在数据层，不是代码层。** 追问定位、检索改写这些看似需要"理解语义"的动作，用"问题数值 vs 已读原文比对""外置词表替换"就能做对，而且比句式匹配健壮——因为它们消费的是工具观察，不是对用户说法的猜测。
2. **代码级防线 > 提示词约束。** "引用必须逐字"写进 prompt 只是建议，finish 校验器逐字回查观察记录才是保证；模型（或 Mock 策略）想虚报，状态会被强制改成 INVALID_CITATION。
3. **Mock 也有价值，但边界要诚实。** Mock 策略同样解析观察再决策，所以离线也能验证流程与状态机；但它不证明真实模型的决策质量——这个边界写进了 README、docs/03 和每份 trace 的头部。

## 3. 已知不足与下一步

1. **真实模型未验证**：当前无 API key，examples 全为 Mock 产物。下一步：配 `.env` 后 `--llm real` 跑冒烟，重点观察首查措辞（A4 可能直接命中，使改写路径不复现）与引用转述（会被校验器拦截，属预期行为）。
2. **冲突误报可能**：两份文档措辞不同但语义相同时会误报冲突；此时输出为"双引用 + 请确认"，不会给出错误答案，但会多一轮确认。
3. **检索是关键词计分**：非向量检索，同义但不含关键词的问法需走改写路径；这是刻意设计（A4 依赖），但意味着真实知识库需要配好 keywords。

## 4. 如果重做一次

会把 finish 校验器在一开始就设计进去，而不是写完策略再补——初版有几处 citation 构造依赖"整段 excerpt"的隐式约定，后来加校验器时被迫核对每一处引用构造点。先定协议，再写实现。

## 5. 候选人补充

**我认为最难的一步**：不是写那个循环，循环本身百来行。难的是发现自己第一版"测试全绿"是假象——冲突判定靠抓"N 天"，追问靠匹配"哪份/那份"，数据一换就穿帮。把这三处全部改成"看数据说话"花的时间超过写初版，但改完这道题才站得住。

**我自己的收获**：判断一个 Agent 可不可信，不看它答对多少，看它换一组数据还认不认账。以及红线上宁可机器多拦、不能人嘴放行——校验器拦错的代价是多一轮确认，放错引用的代价是整题作废。

**下一步想做的**：找一个 OpenAI 兼容的 key 把 real 模式跑起来，专门看两件事——模型首查会不会直接用制度用语（那样"改写再查"路径就不复现了），以及它转述引用时会被校验器拦掉多少。这两个数字能告诉我 Mock 和真实模型的差距到底在哪。
